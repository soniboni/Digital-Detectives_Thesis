## Column Structure Analysis

### LogFile CSVs
```
Columns: LSN, EventTime(UTC+8), Event, Detail, File/Directory Name, Full Path,
         CreationTime, ModifiedTime, MFTModifiedTime, AccessedTime, Redo,
         Target VCN, Cluster Index
```

**Key Fields:**
- `LSN`: LogFile Sequence Number (unique identifier)
- `Detail`: Contains forensic details about the event
- `Event`: Event type (e.g., "Updating MFTModified Time")
- Timestamp fields: CreationTime, ModifiedTime, MFTModifiedTime, AccessedTime

**Example:**
```
LSN=8713791615, Event="Update Resident Value",
Detail="", File/Directory Name="dropboxstatus-connecting@2x.png"
```

### UsnJrnl CSVs
```
Columns: TimeStamp(UTC+8), USN, File/Directory Name, FullPath, EventInfo,
         SourceInfo, FileAttribute, Carving Flag, FileReferenceNumber,
         ParentFileReferenceNumber
```

**Key Fields:**
- `USN`: Update Sequence Number (unique identifier)
- `EventInfo`: Event type (e.g., "File_Closed", "File_Created", "Basic_Info_Changed")
- **CRITICAL**: NO "Detail" field in raw UsnJrnl CSVs!

**Example:**
```
USN=1291845632, EventInfo="File_Closed",
File/Directory Name="dsreg.dll.mui"
```

### Suspicious CSVs (Ground Truth)
```
Columns: source, lsn/usn, category, detail
```

**Key Fields:**
- `source`: "logfile" or "usnjrnl" (indicates which artifact detected the suspicious activity)
- `lsn/usn`: The LSN (if source=logfile) or USN (if source=usnjrnl) identifier
- `category`: Pre-labeled category (e.g., "Timestamp Manipulation", "Execution of Suspicious Programs", "Deletion of Document File")
- `detail`: Detailed forensic description including timestomping patterns

**Example (LogFile source):**
```
source=logfile, lsn/usn=8730038250, category="Timestamp Manipulation",
detail="[Suspicious] $SI timestamp of NewFileTime_SI_C_Manipulation.dll is changed to the past.
(Zero in changed timestamp's 100-nanoseconds) => CreationTime : 2023-12-23 00:21:36 ->
2022-12-23 00:21:50(Zero in 100-nanoseconds)"
```

**Example (UsnJrnl source):**
```
source=usnjrnl, lsn/usn=1328063200, category="Timestamp Manipulation",
detail="[Suspicious] The timestamp of NewFileTime_SI_C_Manipulation.dll may have been manipulated.
(Zero in CreationTime's 100-nanoseconds) => ((CreationTime : 2022-12-23 00:21:50(Zero in 100-nanoseconds))
!= (Creation Event Time : 2023-12-23 00:21:36))"
```

## CRITICAL DISCOVERY

### The Detail Field Only Exists in Suspicious CSVs for UsnJrnl Records

**Previous Assumption (WRONG):**
- Raw UsnJrnl CSVs have a "detail" field that we can check for "Zero in 100-nanoseconds"

**Reality (CORRECT):**
- Raw UsnJrnl CSVs have NO "detail" field
- The "detail" field with timestomping patterns is ONLY in Suspicious CSVs
- Suspicious CSVs are generated by NTFS Artifact Analysis Tool (Oh et al.'s tool)
- Suspicious CSVs contain PRE-LABELED ground truth with forensic analysis

### Implications for Phase 1 Data Processing

**Old Approach (Won't Work):**
```python
# This FAILS because raw UsnJrnl CSVs don't have 'detail' field!
usn_zero_nano = df['usn_detail'].fillna('').str.contains(
    'Zero in 100-nanoseconds', case=False, na=False
)
```

**New Approach (Correct):**
1. Load all LogFile CSVs (has Detail field)
2. Load all UsnJrnl CSVs (no Detail field)
3. **Load all Suspicious CSVs** (has detail field for BOTH sources)
4. **Smart merge** that incorporates Suspicious information:
   - Map suspicious logfile records to LogFile CSV by LSN
   - Map suspicious usnjrnl records to UsnJrnl CSV by USN
   - Add `is_flagged_suspicious` label
   - Add `suspicious_category` field
   - Add `suspicious_detail` field
5. Extract features from suspicious_detail for flagged records

## Timestomping Patterns in Suspicious CSVs

Based on analysis of sample Suspicious CSVs, multiple patterns exist:

### Pattern 1: Zero in 100-nanoseconds
```
"Zero in changed timestamp's 100-nanoseconds"
"Zero in CreationTime's 100-nanoseconds"
```
- Signature of SetFileTime() API usage
- Most common timestomping technique

### Pattern 2: Using Another File's Timestamp
```
"Using another normal file's timestamp"
"CreationTime(2022-09-08 11:07:35) and ModifiedTime(2022-09-08 11:07:35) are same as svchost.exe"
```
- Attacker copies timestamp from legitimate system file
- More sophisticated evasion technique

### Pattern 3: System Time Manipulation
```
"The system time reversal has occurred"
```
- Attacker changes system clock before creating files
- Rare but detectable pattern

### Other Suspicious Categories
- "Execution of Suspicious Programs" (e.g., "NewFileTime (Timestamp Manipulation) has been executed")
- "Deletion of Document File"
- "Traces of Suspicious Programs"

## Revised Phase 1 Strategy

### Step 1: Load Raw Artifacts
- Load all LogFile CSVs from PE and APT training datasets
- Load all UsnJrnl CSVs from PE and APT training datasets

### Step 2: Load Ground Truth
- Load all Suspicious CSVs from PE and APT training datasets
- Parse suspicious records into two groups:
  - logfile_suspicious: records with source='logfile'
  - usnjrnl_suspicious: records with source='usnjrnl'

### Step 3: Smart Merge
- Merge LogFile + logfile_suspicious by LSN
- Merge UsnJrnl + usnjrnl_suspicious by USN
- Combine both sources into unified dataset
- Preserve ALL fields:
  - LogFile fields (including lf_detail from LogFile CSV)
  - UsnJrnl fields (EventInfo, SourceInfo, etc.)
  - Suspicious fields (suspicious_category, suspicious_detail, is_flagged_suspicious)

### Step 4: Feature Extraction (Phase 2)
Now we can correctly extract zero_in_nanoseconds:
```python
# Check LogFile Detail field (for logfile records)
lf_zero_nano = df['lf_detail'].fillna('').str.contains(
    'Zero in 100-nanoseconds', case=False, na=False
)

# Check Suspicious Detail field (for ALL flagged records)
suspicious_zero_nano = df['suspicious_detail'].fillna('').str.contains(
    'Zero in 100-nanoseconds', case=False, na=False
)

# Combine: True if EITHER source shows zero nanoseconds
df['zero_in_nanoseconds'] = lf_zero_nano | suspicious_zero_nano
```
