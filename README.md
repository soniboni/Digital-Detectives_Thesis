# Digital Detectives - NTFS Timestomping Detection

**Machine Learning-Based Detection of Timestamp Manipulation in NTFS File Systems**

This repository contains a thesis project focused on developing machine learning models to detect timestamp manipulation (timestomping) in NTFS filesystems using $LogFile and $UsnJrnl artifacts.

---

## Current Status: Phase 2 - Feature Engineering (Branch: `model-training-soni-4`)

### Why Retraining?

Previous ML models failed on external datasets (0% detection on Lone Wolf dataset). Root cause analysis revealed:

## Critical Discovery: Suspicious CSVs

### Why This Matters

**Raw UsnJrnl CSVs do NOT have a detail field!**

- **LogFile CSVs** have a `Detail` column with forensic patterns
- **UsnJrnl CSVs** only have `EventInfo` (e.g., "File_Closed", "Basic_Info_Changed")
- **Suspicious CSVs** contain pre-labeled ground truth with detail field for BOTH sources

### Suspicious CSV Structure

```csv
source,lsn/usn,category,detail
usnjrnl,239046272,Timestamp Manipulation,"[Suspicious] The timestamp of DeathToll.jpg may have been manipulated. (Zero in CreationTime's 100-nanoseconds)"
logfile,8730038250,Timestamp Manipulation,"[Suspicious] $SI timestamp changed to the past. (Zero in changed timestamp's 100-nanoseconds)"
```

- `source`: "logfile" or "usnjrnl" (indicates which artifact detected the activity)
- `lsn/usn`: LSN (if logfile) or USN (if usnjrnl) - unique identifier for mapping
- `category`: Pre-labeled category (e.g., "Timestamp Manipulation")
- `detail`: Forensic description including "Zero in 100-nanoseconds" patterns

### Impact on Feature Extraction

**Old approach (BROKEN)**:
```python
# Only checks LogFile detail - misses UsnJrnl-only files!
df['zero_in_nanoseconds'] = df['lf_detail'].str.contains('Zero in 100-nanoseconds')
```

**New approach (FIXED)**:
```python
# Must merge with Suspicious CSVs and check suspicious_detail for BOTH sources
lf_zero = df['suspicious_detail_lf'].str.contains('Zero in 100-nanoseconds')
usn_zero = df['suspicious_detail_usn'].str.contains('Zero in 100-nanoseconds')
df['zero_in_nanoseconds'] = lf_zero | usn_zero
```

## Methodology Overview

### Base Research Paper

This project implements methodology from:

**Oh, Lee, and Hwang (2024)** - "Forensic Detection of Timestamp Manipulation for Digital Forensic Investigation"
Published in IEEE Access ([DOI: 10.1109/ACCESS.2024.10517044](https://ieeexplore.ieee.org/document/10517044))

### Detection Approach

1. **Cross-artifact correlation**: Merge $LogFile and $UsnJrnl events for the same file
2. **Timestomping pattern detection**:
   - Zero nanoseconds (SetFileTime() API signature)
   - Time Reversal events (timestamps moved to past)
   - Cross-artifact validation (both artifacts agree = high confidence)
3. **File system tunneling detection**: Separate benign Windows behavior from attacks
4. **ML classification**: Train models on forensic features to detect timestomped files

### Prototype Outputs

The detection system generates four output files:

1. **flagged_files.csv**: High-confidence timestomped files for investigator review
2. **predictions_with_features.csv**: All predictions with feature values for analysis
3. **predictions.csv**: Complete predictions with confidence scores
4. **summary_report.txt**: Human-readable summary statistics

## Retraining Pipeline (6 Phases)

### Phase 1: Data Cleaning & Smart Merging

**Goal**: Merge LogFile, UsnJrnl, and Suspicious CSVs while preserving ground truth

**Key Steps**:
1. Load all 18 training datasets (PE + APT)
2. Merge LogFile + Suspicious (by LSN)
3. Merge UsnJrnl + Suspicious (by USN)
4. Combine LogFile + UsnJrnl (outer join to preserve all records)
5. Add `is_flagged_suspicious` label
6. Create ground truth labels (1 = timestomped, 0 = benign)

**Output**: `data/processed/Phase 1 - Merged Data/all_cases_combined.csv`

### Phase 2: Feature Engineering

**Goal**: Extract forensic features including fixed zero nanoseconds detection

**Features** (~15-20 total):
- **Forensic patterns**: zero_in_nanoseconds, cross_artifact_validation_score, has_logfile_evidence
- **Temporal features**: event_frequency_per_file, events_in_1min_window, events_in_5min_window
- **File characteristics**: is_executable, is_archive, path_depth, filename_length

**Critical Fix**:
```python
# Extract zero nanoseconds from suspicious_detail (BOTH LogFile AND UsnJrnl)
lf_zero_nano = df['suspicious_detail_lf'].str.contains('Zero in 100-nanoseconds')
usn_zero_nano = df['suspicious_detail_usn'].str.contains('Zero in 100-nanoseconds')
df['zero_in_nanoseconds'] = lf_zero_nano | usn_zero_nano
```

**Output**: `data/processed/Phase 2 - Features/all_cases_combined_features.csv`

### Phase 3: Model Training & Comparison

**Goal**: Train and evaluate 5 ML algorithms

**Algorithms**:
1. Random Forest (ensemble baseline)
2. XGBoost (gradient boosting)
3. LightGBM (fast gradient boosting)
4. Logistic Regression (linear baseline)
5. Neural Network (MLP)

**Evaluation Metrics**:
- Recall ≥ 95% (must detect timestomped files)
- Precision ≥ 80% (minimize false positives)
- F1-Score ≥ 0.85

**Output**: Model comparison report, best algorithm selected

### Phase 4: Hyperparameter Tuning

**Goal**: Optimize best algorithm from Phase 3

**Method**: GridSearchCV with 5-fold cross-validation

**Output**: `models/best_model_tuned.pkl`

### Phase 5: Prototype Notebooks & Validation

**Goal**: Create production-ready detection notebooks and validate on Lone Wolf

**Prototype Notebooks**:
1. `01_Load_Data.ipynb` - Load and merge raw CSVs
2. `02_Feature_Engineering.ipynb` - Extract features
3. `03_Run_Detection.ipynb` - Run trained model
4. `04_View_Results.ipynb` - Visualize results

**Critical Validation**: Lone Wolf dataset
- Target: 12/12 timestomped files detected at ≥70% confidence
- All 12 files should have `zero_in_nanoseconds = True`
- False positive rate <5%

**Output**: Prototype notebooks + Lone Wolf validation report

### Phase 6: Autopsy Integration

**Goal**: Develop Autopsy Ingest Module for operational use

**Module**: Automatically detects and flags timestomped files during forensic acquisition

**Output**: Working Autopsy plugin
