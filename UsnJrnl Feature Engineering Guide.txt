USNJRNL FEATURE ENGINEERING GUIDE (OPTIMIZED)
=============================================

## STEP 1: AGGRESSIVE EVENT FILTERING

### Three-Stage Filtering Strategy

**Stage 1: Keep ALL Basic_Info_Changed Events**
- These are potential timestomping events (core detection)
- Count: ~34K events per dataset

**Stage 2: Keep FIRST File_Created Event Per File**
- One creation event per FileReferenceNumber (for creation time comparison)
- Reduces duplicate creation events (same file created multiple times in journal)
- Count: ~55K events per dataset (one per unique file)

**Stage 3: Keep Delete/Rename Events at Monitored Paths ONLY**
- Only keep delete/rename events at paths where we have creation events
- Rationale: Tunneling can only affect files we're monitoring
- Filters out 56% of delete/rename events at irrelevant paths
- Count: ~50K events per dataset (down from 114K)

### Implementation
```python
# Stage 1: All BDP events
bdp_events = usnjrnl[
    usnjrnl['EventInfo'].str.contains('Basic_Info_Changed', na=False)
].copy()

# Stage 2: First creation per file
creation_events = usnjrnl[
    usnjrnl['EventInfo'].str.contains('File_Created', na=False)
].sort_values('TimeStamp(UTC+8)').groupby('FileReferenceNumber').first().reset_index()

# Stage 3: Delete/Rename at monitored paths only
monitored_paths = set(creation_events['FullPath'].dropna().unique())
delete_rename_events = usnjrnl[
    (usnjrnl['EventInfo'].str.contains('File_Deleted|File_Renamed', na=False)) &
    (usnjrnl['FullPath'].isin(monitored_paths))
].copy()

# Combine and deduplicate
usnjrnl_filtered = pd.concat([
    bdp_events,
    creation_events,
    delete_rename_events
]).drop_duplicates(subset=['USN']).copy()

What Gets Dropped (62% of Data)
Pure data operations: Data_Added, Data_Overwritten, Data_Truncated (alone)
Metadata changes: Access_Right_Changed, Extended_Attr_Changed (alone)
Duplicate creation events: 2nd, 3rd, ... creation events for same file
Delete/Rename at unmonitored paths: Events at paths we're not tracking
File_Closed events (alone): Not useful without Basic_Info_Changed
Event Variations DON'T Matter
You'll see 120+ event combinations, but they collapse to binary features:

File_Created                                    → has_file_created = 1
File_Created / Data_Added                       → has_file_created = 1
File_Created / Data_Added / File_Closed         → has_file_created = 1, has_file_closed = 1
File_Created / Extended_Attr_Changed            → has_file_created = 1
ALL variations become just 3 binary features:
has_basic_info_changed
has_file_closed
has_file_created
STEP 2: TIMESTAMP PARSING
Handle CSV Mangling
Timestamps in CSV may have : instead of . separator Format: MM/DD/YYYY HH:MM:SS:mmm (colon-separated, variable length milliseconds)
Normalization Function

def normalize_timestamp(ts_str):
    if pd.isna(ts_str):
        return None
    
    parts = str(ts_str).split(' ')
    if len(parts) != 2:
        return None
    
    date_part, time_part = parts[0], parts[1]
    time_components = time_part.split(':')
    
    if len(time_components) < 3:
        return None
    
    # Take first 3 digits of milliseconds (handle 3 or 4 digit cases)
    ms = time_components[3][:3] if len(time_components) == 4 else '000'
    
    return f"{date_part} {time_components[0]}:{time_components[1]}:{time_components[2]}.{ms}"
Parse EventTime (2-digit year)

usnjrnl_filtered['EventTime'] = pd.to_datetime(
    usnjrnl_filtered['TimeStamp(UTC+8)'].apply(normalize_timestamp),
    format='%m/%d/%y %H:%M:%S.%f',  # Note: %y for 2-digit year
    errors='coerce'
)
Parse MFT Timestamps (4-digit year)

for col in ['SI_CreationTime', 'SI_ModifiedTime', 'SI_AccessedTime']:
    formatted_col = f'{col}_Formatted'
    usnjrnl_filtered[col] = pd.to_datetime(
        usnjrnl_filtered[formatted_col].apply(normalize_timestamp),
        format='%m/%d/%Y %H:%M:%S.%f',  # Note: %Y for 4-digit year
        errors='coerce'
    )
STEP 3: FILE-LEVEL FEATURE CALCULATION
Group by FileReferenceNumber
Each file (identified by FRN) gets these features:
file_event_count: Number of events for this file
file_has_creation: 1 if File_Created event exists, 0 otherwise
file_creation_time: Timestamp of first File_Created event
file_has_bdp: 1 if BDP (Basic_Info_Changed + File_Closed) exists
file_last_bdp_timestamp: Timestamp of last BDP event
file_has_tunneling: 1 if tunneling detected (see Step 4)
file_behavior_counter: Score 0-5 indicating suspicion level
STEP 4: TUNNELING DETECTION (CRITICAL!)
What is Tunneling?
Legitimate Windows feature where:
File A deleted/renamed at path X
File B created at SAME path X within 15 seconds
File B inherits File A's creation time
This LOOKS like timestomping but isn't malicious
Vectorized Detection (Fast - Completes in Seconds)

# 1. Filter to creation events only
creation_events = usnjrnl_filtered[
    usnjrnl_filtered['EventInfo'].str.contains('File_Created', na=False)
].copy()

# 2. Filter to delete/rename events only
delete_rename_events = usnjrnl_filtered[
    usnjrnl_filtered['EventInfo'].str.contains('File_Deleted|File_Renamed', na=False)
].copy()

# 3. Merge on FullPath (same path = potential tunneling)
tunneling_candidates = creation_events.merge(
    delete_rename_events,
    on='FullPath',
    how='inner',
    suffixes=('_created', '_deleted')
)

# 4. Filter to different FileReferenceNumbers (DIFFERENT files!)
tunneling_candidates = tunneling_candidates[
    tunneling_candidates['FileReferenceNumber_created'] != 
    tunneling_candidates['FileReferenceNumber_deleted']
]

# 5. Calculate time difference (creation - delete/rename)
tunneling_candidates['time_diff'] = (
    tunneling_candidates['EventTime_created'] - 
    tunneling_candidates['EventTime_deleted']
).dt.total_seconds()

# 6. Tunneling = delete/rename happened 0-15 seconds BEFORE creation
tunneling_pairs = tunneling_candidates[
    (tunneling_candidates['time_diff'] > 0) &
    (tunneling_candidates['time_diff'] <= 15)
]

# 7. CRITICAL SANITY CHECK: SI-C diff must be < 1 day
# Real tunneling won't cause huge timestamp discrepancies
tunneling_pairs_with_sic = tunneling_pairs.merge(...)
tunneling_pairs_with_sic['si_c_diff'] = abs(...)

valid_tunneling = tunneling_pairs_with_sic[
    tunneling_pairs_with_sic['si_c_diff'] <= 86400  # < 1 day
]

# 8. Mark files with valid tunneling
tunneling_frns = set(valid_tunneling['FileReferenceNumber_created'].unique())
file_features_df['file_has_tunneling'] = file_features_df.index.isin(tunneling_frns).astype(int)
Why Sanity Check is CRITICAL
Without SI-C diff check, you'll incorrectly mark timestomped files as tunneling:
Timestomped file: SI-C diff = 5 days (425K seconds) → NOT tunneling, attacker manipulation
Real tunneling: SI-C diff < 15 seconds typically → Legitimate Windows behavior
Threshold: Filter out cases where SI-C diff > 86400 seconds (1 day)
STEP 5: BEHAVIOR COUNTER CALCULATION
Logic (Per File)

counter = 0

# Case 1: Creation event vs SI-C comparison
if file_has_creation AND |SI_CreationTime - file_creation_time| > 5 seconds:
    counter += 1

# Case 2: Last BDP vs SI-C comparison  
if file_has_bdp AND |SI_CreationTime - file_last_bdp_timestamp| > 5 seconds:
    counter += 1

# Case 3: Tunneling adjustment
if counter >= 1:
    if file_has_tunneling:
        counter -= 1  # Legitimate explanation (Windows feature)
    else:
        counter += 2  # More suspicious (no legitimate explanation)

# Final: counter ranges 0-5
# 0 = clean
# 1 = slightly suspicious
# 2-3 = suspicious
# 4-5 = highly suspicious
